# Стартовый комплект Serpens SDD

Комплект устанавливает системное хранилище SDD для проекта и процесс OpenSpec
для каждого репозитория. После зеркалирования нужных бинарных файлов и npm-пакета
он работает в закрытой сети.

Начните с [`docs/SETUP.md`](docs/SETUP.md): это инструкция по установке в новой
рабочей копии. Существующая рабочая копия переходит на новую редакцию комплекта
по [`docs/UPGRADE.md`](docs/UPGRADE.md). Ежедневная работа и восстановление
описаны в [`docs/OPERATIONS.md`](docs/OPERATIONS.md).

## Итоговая структура

```text
<workspace>/
├── serpens-sdd/                  # этот комплект: настройки, команды, навыки
└── system-store/              # отдельный Git-репозиторий
    ├── .gitmodules            # список репозиториев — отдельного файла-описи нет
    ├── openspec/              # межрепозиторные контракты и ADR
    ├── serpens/
    └── submodules/
        ├── <repository-a>/
        └── <repository-b>/
```

Если доступен MCP проекта, список репозиториев берётся из него. Те же
нормализованные строки можно заполнить вручную, поэтому MCP не является
зависимостью установщика. Комплект содержит собственные навыки `spns-*`. Внешний
Superpowers не требуется.

## Состав

- `system-store-template/`: обычные файлы для соседнего системного хранилища;
- синхронизация подмодулей, контроль Git-состояния, проверки и индексы: доступны через токен `<serpens-sdd>` в командах и навыках, реализованы пакетом `@fresh-fx59/serpens-sdd` и генерируемой заглушкой `serpens/bin/serpens-sdd` в каждом репозитории;
- `commands/`: семь шаблонов Serpens-команд с явными вызовами OpenSpec;
- `skills/`: шесть самостоятельных Serpens-навыков;
- `templates/`: шаблоны исследования, ADR, контракта, стека тестирования, фактов порта, ветвления и правил доставки;
- `config/`: пример списка репозиториев и пример lefthook;
- `slides/`: доклад и его исходник для правки.

Приёмочные наборы, которые проверяют этот комплект, лежат рядом с ним в хранилище
знаний, а не внутри него.

Шаблон специально не содержит вложенного Git-репозитория. Установка копирует
его рядом с `serpens-sdd`, инициализирует Git и не изменяет существующее хранилище.
