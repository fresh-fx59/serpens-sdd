# Branching and commit conventions

**Home:** `system-store/conventions/branching.md`. This is the single source of truth for the whole
estate. Repos and agents reference it; they do not restate it.
**Enforced by:** `tools/serpens-sdd git-naming` via lefthook (`commit-msg` + `pre-push`) in every repo.
Prompts advise, checks enforce — never fix a red check by weakening it.

## Branch name

```
feature/ABCD-1234
```

- `feature/` prefix, then the tracker ticket key.
- Ticket key = uppercase project key, dash, number. `ABCD-1234`.
- Nothing after the number. `feature/ABCD-1234-add-invoices` is rejected — the description belongs
  in the commit message and the PR title, not the branch.
- One change folder = one branch = one ticket. This is OpenSpec's team workflow (change = folder =
  branch) and what makes the tracker linkage work.

**Exempt** (long-lived, not created by the flow): `main`, `master`, `develop`,
`release/*`, `hotfix/*`, `support/*`.

## Commit message

```
feat(ABCD-1234): commit message text
```

- `<type>(<TICKET>): <text>` — note the parentheses, the colon, and the single space after it.
- Allowed types: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `perf`, `build`, `ci`,
  `revert`.
- **The ticket in the message must match the ticket in the branch.** A mismatch links work to the
  wrong story and nobody notices until the report. The check rejects it.
- Merge, revert, `fixup!` and `squash!` subjects are generated by git, not authored — they are
  skipped.

## Who does what

- **The agent** creates the branch and writes the commit message during the `spns-spec` handover
  step and throughout `spns-implement`. It must follow this file — that is why the pattern is
  repeated in each repo's agent context file.
- **The dev** never renames a branch to satisfy the check by dropping the ticket. If the ticket is
  wrong, the branch is wrong.
- **DevOps** owns this file and the hook wiring. A change here is a change to every repo.

## Verifying the hooks actually fire

A hook that is installed but never runs is worse than no hook — everything looks green. A **global**
`core.hooksPath` silently overrides every repo's local hooks, including lefthook's install. Check it:

```bash
git config core.hooksPath          # expect empty, or this repo's own hooks dir
```

If it points somewhere global, the disposer and these checks are not running. Fix the machine, then
prove it with a deliberate bad commit that gets rejected.
